# CampusEvents — план проекта

Афиша студенческих мероприятий: студенты находят события и записываются на них, организаторы создают события и видят участников, админ их модерирует.

## Команда

| Участник | Зона ответственности         | Кто    |
|----------|------------------------------|--------|
| 1        | Пользователи и доступ        | Даша   |
| 2        | События                      | Алдияр |
| 3        | Регистрации и избранное      | Айжан  |
| 4        | Админка, комментарии, деплой | Даурен |

## Технологии

- Next.js (App Router), TypeScript, Tailwind CSS
- PostgreSQL + Prisma (ORM), валидация — Zod
- Аутентификация — Better Auth
- Защита маршрутов — `proxy.ts` (в Next.js до 16 версии этот файл назывался `middleware.ts`)
- Деплой — Vercel + облачная база (Neon или Supabase)

## Модель данных

- **User** — роль: `USER`, `ORGANIZER` или `ADMIN`
- **Category**
- **Event** — название, описание, место, дата, лимит мест, статус (`PENDING` / `PUBLISHED`), организатор, категория
- **Registration** — пользователь + событие, пара уникальна
- **Favorite** — пользователь + событие, пара уникальна
- **Comment** — пользователь, событие, текст, дата создания

## Правила работы

- Работаем через ветки `feature/<кратко>` и pull request в `main`. Ревью по кругу: 1 → 2 → 3 → 4 → 1.
- Сообщения коммитов: `feat: ...`, `fix: ...`, `docs: ...`, `chore: ...`.
- Схему Prisma меняет только владелец модели, через PR. После merge все применяют миграцию.
- Галочки в этом файле ставим в своих pull request.

### Участник 2 — События

- [ ] API событий (Route Handlers + Zod): создать, список, одно событие, изменить, удалить; править можно только свои

**Готово, когда:** организатор создаёт событие, а после одобрения оно появляется в списке.

### Участник 3 — Регистрации и избранное

- [ ] API: записаться и отменить запись; пара «пользователь + событие» уникальна; на прошедшие события записаться нельзя

**Готово, когда:** лимит мест нельзя превысить, организатор видит участников, избранное сохраняется между сессиями.

### Участник 4 — Админка, комментарии, деплой
