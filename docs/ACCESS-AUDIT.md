# Аудит доступа (этап 5)

Дата: 27 ноября 2026. Проверено на тестовой ветке базы `dev` (Neon) и локальном сервере с `NEXT_PUBLIC_USE_MOCKS=false`.

## Как проверяли

Каждую страницу и каждый API-маршрут вызывали под четырьмя ролями: гость, студент, организатор, админ. Для чужих данных — от имени второго организатора и второго студента. Отдельно проверили блокировку пользователя и регистрацию через Better Auth напрямую, в обход форм сайта.

Всего **147 автоматических проверок**, после исправлений все проходят.

## Как устроена защита

- `src/proxy.ts` пускает в закрытые разделы только с cookie сессии, иначе отправляет на `/login`.
- Роль проверяется в шаблонах разделов `(student)`, `(organizer)`, `(admin)` через `requireRole()` и на странице профиля через `requireAnyRole()`. Чужая роль попадает на `/no-access`.
- В каждом API роль проверяется через `requireApiRole()`: гость получает 401, чужая роль — 403. Чужие события, записи и комментарии дают 403 или 404, чтобы не выдавать, что запись существует.
- Заблокированный пользователь считается гостем: его старая сессия перестаёт работать, войти заново он не может.

## Найдено и исправлено

| # | Проблема | Чем грозило | Исправление | Зона |
|---|----------|-------------|-------------|------|
| 1 | `/api/favorites` для организатора и админа отвечал **500** вместо **403** | Данные не утекали, но API вёл себя неправильно, клиент получал «внутреннюю ошибку» | Маршрут проверяет роль студента через `requireApiRole("STUDENT")` | Избранное (Айжан) |
| 2 | Регистрация и смена пароля **напрямую через Better Auth** принимали слабый пароль (`onlyletters`, `12345678`) — правило «буква + цифра» работало только в формах сайта | Можно было обойти требования к паролю | Хук Better Auth проверяет пароль общей схемой `passwordSchema` для `/sign-up/email` и `/change-password` | Доступ (Даша) |

## Проверено и в порядке

- Подставить себе роль при регистрации нельзя: запрос с `"role": "ADMIN"` создаёт обычного студента (поле `role` закрыто для ввода).
- Админ не может понизить собственную роль.
- После попыток без прав роли и статусы в базе не меняются.
